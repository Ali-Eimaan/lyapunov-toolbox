# Benchmarks

All numbers are generated by `benchmark_row` in `julia/src/roa_estimation.jl`,
which takes a system and an `ROAResult` and prints a Markdown row.
Numbers are **never** entered by hand.

### How to populate

```bash
julia --project=julia -e '
using LyapunovToolbox
sys = van_der_pol(reversed=true)
res = synthesize_lyapunov(sys; opts=SOSOptions(V_degree=4, vs_iterations=10))
LyapunovToolbox.benchmark_row(sys, res)
'
```

The output is a Markdown table row that can be pasted into the table above.
Do the same for `inverted_pendulum(recast=:trig)`, `unicycle_with_obstacle()`,
and `consensus_network(n=5)`.

## Interpretation

- **ρ (bisect):** The certified level-set for the initial quadratic V.
  This is the baseline; the V-s iteration must beat it.
- **ρ (V-s):** The certified level after V-s iteration (always ≥ ρ(bisect)).
- **β:** The shape-set containment level (see `beta_step`). Larger β means
  the sublevel set fills more of the shape.
- **Vol (cert):** Monte Carlo volume estimate of the certified sublevel set.
- **Vol (true):** Monte Carlo estimate of the true ROA boundary (forward
  simulation); this is empirical, not a proof.
- **% captured:** Vol(cert) / Vol(true) × 100%. A certificate that
  captures < 10% of the true ROA is not useful; one that captures > 80%
  is publication-quality.
- **Time (s):** Wall-clock time including all SDP solves.
- **SDPs:** Number of SDPs solved (bisection iterations + V-s iterations × 3).

## Caveats

1. The "true ROA" is estimated by forward simulation — it is not a proof.
2. The V-s iteration is not monotone in volume (it is in β), so the
   volume number may fluctuate.
3. The SDP solver (Clarabel) is deterministic; the Monte Carlo volume
   estimate is not — run with a fixed seed for reproducibility.
4. For systems with dimension > 2, the volume estimate is only a sanity
   check; the comparison that matters is β.


Nothing in this file may be typed from memory, estimated, or copied from a paper.
Each number is produced by code in this repository, on hardware named below, and
is reproducible with the command given next to its table.

## 7. Caveats

Write these out rather than leaving them implied:

- Solve times are single-run on a laptop under an unspecified thermal state.
  Report the median of five runs and say so, or report a single run and say that.
- "Fraction of true ROA" uses an empirical boundary for every system except Van
  der Pol. It is an estimate at a stated horizon and grid, not a proof.
- Every certified set is an **inner** approximation. None of these numbers is the
  region of attraction; each is a set that provably lies inside it.
- The V–s iteration is a local heuristic. A larger number in this table means a
  better run, not a better system.
